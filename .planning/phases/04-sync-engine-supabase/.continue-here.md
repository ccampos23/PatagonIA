## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Guessing Supabase SDK API signatures | Used `io.github.jan.supabase.auth.signInWith` import paths that don't exist as top-level extensions; built wrong API surface for `signUpWith` and `data` lambda type. | advisory | Introspect the actual JAR via `javap -classpath auth-kt-api.jar -public io.github.jan.supabase.auth.Auth` before writing any Supabase SDK call. |
| Skipping per-task pause checkpoints | User explicitly requested pausing after every task. Default GSD executor runs all 4 tasks of a plan one-shot. | advisory | After every task commit, stop, summary, and ask user before starting next task. |
| Writing local.properties via Edit tool | A prior session in this workspace accidentally blanked out `local.properties` (lost `sdk.dir` and Mapbox token) — gradlew then failed with "SDK location not found". | advisory | Treat `local.properties` as critical state. |
| Using Mockito thenThrow on suspend functions | `thenThrow(AuthException(...))` causes `Checked exception is invalid for this method!` because Kotlin suspend compiles to a continuation-based method. | advisory | Use `thenAnswer { throw AuthException(...) }` instead of `thenThrow(...)` for suspend function mocks. |
