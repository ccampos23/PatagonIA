## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| App → Supabase API | All auth and data API calls over HTTPS |
| Local Storage → Auth Tokens | Session tokens stored on device |

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Spoofing | Auth Flow | mitigate | Use Supabase Auth with HTTPS; never store service_role key in client; use only anon key |
| T-04-02 | Information Disclosure | BuildConfig | mitigate | Store Supabase URL/key in local.properties (gitignored); anon key is public-safe per Supabase design |
| T-04-03 | Tampering | Session | mitigate | Supabase SDK handles JWT validation server-side; client only stores refresh token securely |
| T-04-04 | Elevation of Privilege | user_metadata | mitigate | Never use raw_user_meta_data for authorization decisions (per Supabase security guidelines); store auth data in app_metadata |
</threat_model>
